# Use Case: Remote Execution

This document illustrates the user experience when running `hermes-research` and choosing to execute the research task on a configured remote server.

## Scenario

A user wants to start a research session named "cloud_analysis_v1" on a powerful remote server named "gpu-cluster-1". They will use the "claude-3-opus" model with the default budget. They have one file, `project_brief.md`, and want to pass an extra argument `--temperature 0.5` to the underlying `hermes` command.

## User Interaction Flow

1.  **User invokes the command:**

    ```bash
    hermes-research project_brief.md -c "--temperature 0.5"
    ```

2.  **Application prompts for session name:**

    ```text
    Enter a name for this research session: cloud_analysis_v1
    ```

3.  **Application prompts for model selection:** (Assuming "claude-3-opus", "llama3-local" are configured)

    ```text

    --- Select Model ---
    1: claude-3-opus
    2: llama3-local
    Enter 'q' to cancel
    Choice: 1
    ```

4.  **Application prompts for budget:** (Assuming default is 30)

    ```text
    Enter budget (default: 30): [Enter is pressed]
    ```
    *(User accepts the default)*

5.  **Application prompts for the research query:**

    ```text
    Enter the research prompt (press Meta+Enter or Esc+Enter to finish):
    > Based on the project_brief.md, outline the main research questions
    > and propose a high-level methodology.
    > [Meta+Enter or Esc+Enter is pressed]
    ```

6.  **Application prompts for execution target:** (Assuming "gpu-cluster-1" and "dev-server" are configured remote servers)

    ```text

    --- Select Execution Target ---
    1: Local Execution
    2: gpu-cluster-1
    3: dev-server
    Enter 'q' to cancel
    Choice: 2
    ```

7.  **Application confirms remote execution, performs setup, and starts remote tmux:**

    ```text
    Preparing remote research session 'cloud_analysis_v1' on server 'gpu-cluster-1'...
    Generating remote command script...
    Testing SSH connection to user@gpu-cluster-1... Success.
    Creating remote temporary directory on gpu-cluster-1:/tmp/hermes_research/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/...
    Copying project_brief.md to gpu-cluster-1:/tmp/hermes_research/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/project_brief.md...
    Copying run script to gpu-cluster-1:/tmp/hermes_research/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/run_research.sh...
    Configuring tmux for remote server 'gpu-cluster-1'...
    Creating remote tmux session 'cloud_analysis_v1' on gpu-cluster-1...
    Sending command to remote tmux session...
    Remote research session 'cloud_analysis_v1' started on 'gpu-cluster-1'.
    You can attach to it using: ssh user@gpu-cluster-1 "tmux attach -t cloud_analysis_v1"
    ```

## Result

*   SSH connection to `gpu-cluster-1` is established.
*   A unique temporary directory (e.g., `/tmp/hermes_research/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/`) is created on the remote server.
*   The input file (`project_brief.md`) is copied into the remote temporary directory.
*   A shell script (`run_research.sh`) containing the `hermes` command is generated locally and copied to the remote temporary directory. This script references the input file(s) from the temporary directory but sets the `--deep-research` path to the final intended location (e.g., `/path/to/remote/research/cloud_analysis_v1/`).
*   A new tmux session named `cloud_analysis_v1` is created on the *remote* server `gpu-cluster-1`.
*   A command to execute the `run_research.sh` script *from its temporary location* is sent to the remote tmux session.
*   The local temporary script file is cleaned up.
*   The final research output will be generated by `hermes` in the directory specified by `--deep-research` on the remote server (e.g., `/path/to/remote/research/cloud_analysis_v1/`).
*   *(Note: The remote temporary directory might persist unless explicitly cleaned up.)*
